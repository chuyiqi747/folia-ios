# iOS 音源后端部署指南

> 这是整个 iOS 版能不能真正「听歌」的前提。**App 本身不含任何音源**，
> 所有在线歌曲、歌词、封面都要通过你自己部署的 API 实例中转。

---

## 0. 先理解架构

```
┌─────────────────┐
│  Folia iOS App   │   (WKWebView 里的 React 前端)
│  你的 iPhone      │
└────────┬─────────┘
         │  HTTPS
         ▼
┌─────────────────────────────────────────────┐
│  你自建的 API 层（三种，可只部署需要的）        │
│                                             │
│  ① 网易云 API        NeteaseCloudMusicApiEnhanced
│  ② 酷狗 API          KuGouMusicApi (Web 模式)
│  ③ Folia 自建 API    AI 主题生成 + 歌词代理    │
│                                             │
│  参考实现：仓库的 api/ 与 worker/ 目录         │
└────────┬────────────────────────────────────┘
         │  上游
         ▼
     网易云 / 酷狗 / QQ 音乐服务器
```

**关键约束**：iOS 强制 ATS（App Transport Security），
生产环境**必须全部走 HTTPS**。HTTP 只能用于本地调试，且要在 Info.plist 里开例外。

## 1. 环境变量总表

在项目根目录建 `.env.local`（不要提交到 git）：

| 变量 | 指向什么 | iOS 端要求 |
| --- | --- | --- |
| `VITE_NETEASE_API_BASE` | 你部署的网易云 API 根地址 | **必须 HTTPS** |
| `VITE_KUGOU_API_BASE` | 你部署的 KuGouMusicApi 地址（Web 模式） | **必须 HTTPS** |
| `VITE_QQ_API_BASE` | QQ 音乐 API 地址，或填 `/api/qq` 走同源 | **必须 HTTPS** |
| `VITE_FOLIA_API_BASE` | AI 主题 + 歌词代理的 API 根地址 | **必须 HTTPS** |
| `VITE_AI_PROVIDER` | `google` 或 `openai` | 无 |
| `GEMINI_API_KEY` | Gemini Key | ⚠️ 绝不能写进客户端 |

**这些 `VITE_*` 变量会在构建时被内联进 JS 产物**，
所以里面**只能放公开的 API 地址，绝不能放密钥**。
AI 的密钥全部放在服务端环境变量里（见第 4 节）。

示例 `.env.local`：

```env
# 网易云 API（假设部署在 Vercel）
VITE_NETEASE_API_BASE=https://netease-api-abc123.vercel.app

# 酷狗 API（可选，不用就留空）
VITE_KUGOU_API_BASE=

# AI 主题 + 歌词代理
VITE_FOLIA_API_BASE=https://folia-api-abc123.vercel.app/api

# AI 提供商（密钥在服务端配，这里只声明类型）
VITE_AI_PROVIDER=openai
```

## 2. 部署网易云 API

### 方案 A：Vercel（推荐，最省事）

1. Fork [NeteaseCloudMusicApiEnhanced](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced)
2. Vercel → **Add New → Project** → 导入你的 fork
3. 部署完成后拿到域名，例如 `https://netease-api-abc123.vercel.app`
4. 填进 `.env.local` 的 `VITE_NETEASE_API_BASE`

> ⚠️ Vercel 免费版的 Serverless Function 有执行时长限制。
> 网易云 API 的部分接口（尤其是登录、歌单详情）可能超时。
> 如果遇到 504，改用方案 B。

### 方案 B：Docker 自托管（最稳定）

仓库自带 Compose 编排：

```bash
cd deploy/docker
# 按 README 填好环境变量
docker compose up -d
```

适合有 NAS 或云主机的用户。**必须配反向代理 + 有效证书**，
因为 iOS 不接受自签名的 HTTPS 证书链。

Nginx 最小配置：

```nginx
server {
    listen 443 ssl http2;
    server_name music-api.yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/music-api.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/music-api.yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 关键：网易云有部分接口会用流式响应，关掉缓冲避免音乐卡顿
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

Let's Encrypt 证书用 certbot 一条命令搞定：

```bash
sudo certbot --nginx -d music-api.yourdomain.com
```

## 3. 部署酷狗 API（可选）

只有当你要用酷狗音源时才需要。

1. Fork [KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi)
2. 用它的 Web 模式部署（仓库有 Dockerfile）
3. 把地址填进 `VITE_KUGOU_API_BASE`

> 注意：桌面版 Electron 是**在主进程里直接调用酷狗 Node 模块**，不启 HTTP 服务。
> iOS 没有这个能力，所以必须走独立的 HTTP 实例。

## 4. 部署 Folia 自建 API（AI 主题 + 歌词代理）

这个 API 在两个地方被用：

- **AI 主题生成** —— 根据歌曲情绪生成配色背景，需要 LLM
- **歌词代理** —— 绕过浏览器 CORS 去拉 QQ / 酷狗的歌词文件

### 用 Vercel 部署

1. Fork folia 主仓库（或你的 sonnet fork）
2. Vercel → **Add New → Project** → 导入 fork，
   **保留仓库里的 `vercel.json`**（它定义了 `/api/*` 的路由）
3. 在 **Settings → Environment Variables** 里配一种 AI 提供商：

   使用 OpenAI 兼容接口（DeepSeek / Qwen / Kimi 等）：

   ```
   OPENAI_API_KEY      = sk-xxxxxxxx
   OPENAI_API_URL      = https://api.deepseek.com
   OPENAI_API_MODEL    = deepseek-v4-flash
   OPENAI_API_TEMPERATURE = 0.7
   ```

   或使用 Gemini：

   ```
   GEMINI_API_KEY      = AIzaSyxxxxxxxx
   ```

4. 部署完拿到地址，填进 `.env.local`：

   ```env
   VITE_FOLIA_API_BASE=https://folia-api-abc123.vercel.app/api
   ```

> ⚠️ **密钥安全**：`OPENAI_API_KEY` / `GEMINI_API_KEY` **只填在 Vercel 环境变量里**，
> 绝不能写进 `.env.local` 的 `VITE_*` 变量、也不能进 APK/IPA。
> 这个 API 是给跨域客户端用的，**没有内置访问控制**。
> 如果你部署的是高额度密钥又没有任何限流，别人可以直接白嫖你的额度。
> 建议：在 Vercel 上加一层简单的 Token 校验，或使用低额度、可随时吊销的密钥。

## 5. 把配置构建进 iOS 包

改完 `.env.local` 后，**必须重新构建**才能生效
（`VITE_*` 是构建时内联的，改了环境变量不重新 build 是不会变的）：

```bash
# 1. 构建电容产物
npm run build:capacitor

# 2. 同步到 iOS 工程（把 dist/ 拷进 ios/App/App/public/）
npx cap sync ios

# 3. 打开 Xcode
npx cap open ios

# 4. 在 Xcode 里选模拟器或真机，点运行
```

## 6. 验证后端是否接通

App 跑起来后，按这个顺序排查：

### 6.1 先看首页能不能出内容

能搜到歌、能出封面，说明 `VITE_NETEASE_API_BASE` 通了。

### 6.2 搜到了但点播放没声音

九成是这两个原因：

1. **歌曲源有版权限制 / 需要登录** —— 网易云大量歌曲需要 VIP 或登录才能取到播放地址。
   在 App 里完成扫码登录。
2. **音频 URL 是 HTTP** —— iOS ATS 会直接掐断。打开 Safari 调试
   （Xcode → Safari → 开发 → 你的设备）看 Network 面板，
   如果 request 直接 failed 且没响应，就是被 ATS 拦了。

### 6.3 用 Safari 开发者工具调试 iOS WebView

这是 iOS 上最有效的排查手段：

1. iPhone：设置 → Safari → 高级 → 打开「网页检查器」
2. Mac：Safari → 设置 → 高级 → 勾选「显示网页开发者功能」
3. 用数据线连上 iPhone，在 App 运行状态下：
   Mac Safari → 开发 → [你的 iPhone] → [Folia]
4. 这时你能看到完整的 Console 与 Network，跟调普通网页一样

### 6.4 常见报错对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Failed to fetch` | 后端地址不通 / HTTPS 证书无效 | 用 `curl -I <地址>` 在电脑上验证 |
| `NetworkError` 且无响应 | ATS 拦截 HTTP | 换 HTTPS，或临时在 Info.plist 加例外 |
| `504` | Vercel 函数超时 | 改 Docker 自托管，或换更轻的接口 |
| 登录二维码不显示 | `VITE_QQ_API_BASE` 指向不对 | 确认地址可访问，或改同源 `/api/qq` |
| AI 主题一直转圈 | AI Key 没配或额度空 | 看 Vercel 的 Function Logs |
| 播放几秒后中断 | 后台模式没生效 | 确认 Info.plist 有 `UIBackgroundModes: audio` |

## 7. 部署清单

上线前逐项打勾：

- [ ] 网易云 API 已部署且 **HTTPS 可访问**

- [ ] Folia 自建 API 已部署，AI Key 配在**服务端环境变量**

- [ ] `npm run build:capacitor` 重新构建过
- [ ] Info.plist 已合并 `resources/Info.plist.snippet.xml` 的键
- [ ] 真机测试：搜索 / 播放 / 后台播放 / 锁屏控制 / 切歌
